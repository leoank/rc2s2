### Code findings

Endpoint and request (one chunk, `var fS=...` / `async function qm(e,r)` / `UL`):
- `fS = {plain: "/api/oauth/usage", at_wall: "/api/oauth/usage?at_wall=1&skip_spend=1",
  cedar_ember: "/api/oauth/usage?cedar_ember=1&skip_spend=1"}`. `qm(credentials, read)` does
  `zt.get(path, {timeout: 5000, headers: {"Content-Type": "application/json"},
  refreshOAuth: true, credentials, validateStatus: 2xx})`; `UL(credentials, {read})` wraps it
  (at_wall reads are de-duplicated per host). Debug lines: `fetchUtilization: GET <path>
  (attempt n)`, metric `api_usage_fetch`.
- Request builder `kr(method, path, body, opts)`: default host `"api"` resolves through
  `Ap()` to `BASE_API_URL = "https://api.anthropic.com"`. With no `auth` option the headers
  come from `Lte()`: for a claude.ai login (`kt()` true) that is
  `Authorization: Bearer <oauth access token>` and `anthropic-beta: oauth-2025-04-20`
  (`Ep`), plus `User-Agent` from `XL()`. So the full request is
  `GET https://api.anthropic.com/api/oauth/usage` with those three headers (and
  `Content-Type: application/json`). A 401 triggers one OAuth refresh and a retry
  (`aE`, `oauthRefreshLatch`); 403/429 answers are remembered per bearer for
  `retry-after`, else 5 min (`iS = 300000`), capped at 1 h (`Ym`); auth rejections for 1 h
  (`sS`), behind flag `tengu_federated_robin`.
- Gates: `kt()` = signed in to claude.ai with inference scopes; `Jp()` = the token's scopes
  include `user:profile` (`K9`). Without both the loader returns nothing and
  `rate_limits_available` is false (schema text: "API key, Bedrock, Vertex, or missing
  profile scope").

Cache (same chunk, `var LS=3600000, oh=60000, US=...`):
- Schema `US`: `{fetchedAtMs, accountUuid?, utilization{five_hour{utilization, resets_at},
  seven_day, seven_day_oauth_apps, seven_day_opus, seven_day_sonnet, cinder_cove,
  wattle_ember, extra_usage{is_enabled, monthly_limit, used_credits, utilization, ...},
  limits[{kind, group, percent, resets_at, severity, is_active, scope}]}}` with passthrough,
  i.e. the endpoint body is stored as is; `utilization` values are percent.
- `kFs(utilization, accountUuid, storage)` is the only writer: it skips unless
  `accountUuid` equals the current `oauthAccount.accountUuid`, and skips when the stored
  entry for that account is younger than `oh` = 60 s. So the file is rewritten at most once
  a minute, and only by a successful endpoint read.
- `SOr(storage)` reads it: if `accountUuid` differs from the current login it deletes the key
  (`cachedUsageUtilization: undefined`) and returns null; entries older than `LS` = 1 h are
  ignored (not deleted).
- `CFs(storage)` is the "fresh snapshot" check used before fetching: younger than 60 s and
  not older than the process's last rate-limit header observation
  (`se.lastAppliedObservationAtMs` on the `ih` tracker that parses
  `anthropic-ratelimit-unified-*` response headers). A fresh snapshot answers the read
  without a request ("Usage read answered from a snapshot Ns old; endpoint not asked").
- Logout (`oauth_logout` path) wipes it together with the other caches
  (`i.cachedUsageUtilization = void 0`, next to `startupPrefetchedAt`, `modelAccessCache`,
  ...). That is why the key was gone after the `/login` at 13:45 today.

Who calls the loader (`R` -> `slr` -> `UAn` in the chunk exporting `$An, slr, v7r, UAn`):
1. `/usage` (aliases `/cost`, `/stats`). Interactive: command `S6e` (local-jsx) opens the
   Settings panel `Vs` (tab "Usage"), which seeds from headers or the persisted cache
   (`$An`) and calls `slr` on mount and on `r` (retry). Non-interactive: command `b6e`
   (`supportsNonInteractive: true`, `isEnabled: we()`), whose `call` (`G`) prints the text
   form through `UAn`.
2. SDK control request `{"subtype": "get_usage", "skip_behaviors"?: bool}` (handler `nt`,
   schema `Go`; its description: "For callers that need only the plan rate limits, such as a
   usage meter; the scan reads every transcript touched in the last seven days"). Returns
   `{session{total_cost_usd, total_api_duration_ms, total_duration_ms, total_lines_added,
   total_lines_removed, model_usage}, subscription_type, rate_limits_available,
   rate_limits{five_hour, seven_day, ..., model_scoped[]}, behaviors}`.
3. Nothing else. There is no timer and no startup prefetch of it (the
   `startupPrefetchedAt` block runs `aNt`, `Fvt(Jce)`, `$Rs`, `YOe`, none touch usage); the
   status line's `rate_limits {five_hour, seven_day, spend_limit}{used_percentage,
   resets_at}` is built from `I5()`, the header tracker, not from the cache; the stream-json
   `rate_limit_event` (`rss`) comes from the same tracker. The `at_wall` and `cedar_ember`
   reads (`dn`, `ir`, used when a limit is hit) go through `UL` but never `kFs`.

So: trigger = a `/usage` command or a `get_usage` control request, nothing else; write gate
60 s; read horizon 1 h; cleared on logout and on account change. The one refresh seen in
[[RUN-20261016-r0r0j9]] at the start of an interactive session was a `/usage`, not a startup
fetch.

### For the rc2s2 node daemon

- Cheapest refresh without touching the token: `claude -p "/usage"` in any trusted cwd. No
  model call, about 4 s, writes `cachedUsageUtilization` if the last write is older than
  60 s, and prints the same numbers; the cost is the local transcript scan (every transcript
  of the last seven days). Reading `~/.claude.json` afterwards gives `resets_at` and the
  `limits[]` rows that the text omits.
- If the daemon already holds a stream-json session with the control channel, send
  `{"type": "control_request", "request": {"subtype": "get_usage", "skip_behaviors":
  true}}`: same loader, no transcript scan, structured reply, and it writes the cache too.
- Direct call (for a daemon that leases the OAuth token, see [[EXP-20261016-rq1408]]):
  `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <access
  token>`, `anthropic-beta: oauth-2025-04-20`, `Content-Type: application/json`; the token
  needs the `user:profile` scope. The body is the `utilization` object as stored in the file
  (percent, ISO `resets_at`). Not exercised in this run. Stay at or above the CLI's own
  cadence (one read per 60 s) and honour `retry-after` on 429.
- Interactive sessions never refresh it on their own, so the daemon should not wait for
  them; `fetchedAtMs` is a true age, and the key may be absent right after a login.
