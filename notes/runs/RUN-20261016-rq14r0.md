### 2. Idle vs load
Load: `gpu_load.m`, a Metal compute kernel (20k sin/cos iterations per thread, 4M
threads) dispatched back to back for 8 s, built in the spike dev shell with
`clang -fobjc-arc -framework Metal -framework Foundation gpu_load.m -o gpu_load`.
Sampler: `sample_ioreg.py 16 0.5` (ioreg every 0.5 s); load started at t=3 s.
Full table: `experiments/EXP-20261016-rq1409/ioreg-samples-idle-load.tsv`. Excerpt:

```
t_s   Device%  Renderer%  Tiler%  In use bytes  Alloc bytes
 2.7      0        0        0     225525760    4100014080   idle
 3.8     98        0        0     344227840    4210442240   load started
 5.9     99       37       37     575815680    4453941248   (WindowServer blip)
 8.0    100        0        0     575602688    4389928960
11.8    100        0        0     406929408    4126523392   last loaded sample
12.3      0        0        0     411467776    4100898816   load ended
```
33 dispatches completed in 8 s. `Device Utilization %` tracks the load exactly (0 ->
98-100 -> 0). Renderer/Tiler stay at 0 for a pure compute load and only blip (18-37) when
the window server composites. `In use system memory` moves between ~175 MB and ~576 MB
during the run; it is a system-wide unified-memory figure, not per-process.
