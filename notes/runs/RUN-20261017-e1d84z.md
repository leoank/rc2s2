## Notes
Multi-select: the `answers` value for a `multiSelect: true` question is an array of
the chosen option labels, and Claude Code normalises it to a comma-joined string.

Interactive session under the PTY driver, PermissionRequest hook supplying the answer
(logs in `experiments/EXP-20261016-rq1404/run-multiselect/`). New sink `hook_server_ask.py`
(sibling of `hook_server.py`) reads the answer map verbatim from `ask_answers.json`;
settings `settings-ask-perm.json` (port 7792, `perm` mode); driver
`pty_driver.py`; `claude --model sonnet --permission-mode default`.

Prompt: one question, exact text `Which toppings?`, header `Toppings`, `multiSelect: true`,
options Cheese/Olives/Peppers/Onions. The hook's `PermissionRequest` returned
`decision: {behavior: allow, updatedInput: {...tool_input, answers:
{"Which toppings?": ["Cheese", "Olives"]}}}` — the value an **array of labels**.

What Claude received: the tool normalised the array to a single string. `PostToolUse`
`tool_response.answers` was `{"Which toppings?": "Cheese, Olives"}`, and the `tool_result`
in the transcript read verbatim:

> Your questions have been answered: "Which toppings?"="Cheese, Olives". You can now continue with these answers in mind.

The assistant then printed `Cheese, Olives`. The terminal flashed the checkbox dialog,
then showed `User answered Claude's questions:  · Which toppings? → Cheese, Olives` and
`Allowed by PermissionRequest hook`.

Static read of 2.1.302 (the `answers` validator, `ue`/`Dkt`) agrees: an array is accepted
only when `multiSelect` is true, length `<= optionCount + 1`, each element a string; it is
then joined with `", "` (`Dkt`, CSV-quoting any element containing `", "` or `"`) and stored
as that one string. A plain joined string (e.g. `"Cheese, Olives"`) is also accepted. The
map key must be the exact question text or the whole `answers` object is rejected.
