### Code read first

Strings of the 2.1.302 binary, plain-JS chunks (identifiers are minified and change per
release):

- Refresh is needed when `now + 300000 >= expiresAt` (five-minute buffer, `KC`).
- Refresh = `POST https://platform.claude.com/v1/oauth/token` JSON
  `{grant_type: "refresh_token", refresh_token, client_id, scope}`; the reply's
  `refresh_token` replaces the stored one when present (`refresh_token: K = e` default keeps
  the old one otherwise), `expires_in` and `refresh_token_expires_in` set the two expiries.
- Save is a compare-and-swap under a lock file in the config dir: the new set is written only
  if the stored `refreshToken` is still the one that was posted (or empty); otherwise the
  sibling's newer write is adopted (`adopted_sibling`). Three retries.
- On `invalid_grant` (400/401) the refresh token is marked dead in memory and the stored set is
  cleared to `{accessToken: "", refreshToken: "", expiresAt: 0}` (`tengu_oauth_refresh_token_cleared_on_disk`).
- A running session watches the credential store (mtime of `.credentials.json`, or a version
  probe on the keychain backend) and re-reads it when it changes (`credentialsChangedOnDisk`).
- Keychain service name with `CLAUDE_CONFIG_DIR` set: `Claude Code-credentials-<sha256(dir)[:8]>`;
  `CLAUDE_SECURESTORAGE_CONFIG_DIR` overrides which directory the hash is taken from (empty
  string selects the unsuffixed item).

### What this says

1. **A refresh rotates both tokens and revokes the previous set at once.** A0 stopped working
   within a minute of A's refresh even though it had six hours left, and R0 was
   `invalid_grant` afterwards. Two copies of one grant cannot both stay alive past the first
   refresh. The owner's interactive session was the collateral damage.
2. **Separate logins are separate grants.** The owner's `/login` did not touch A1/R1. So the
   hub can hold one grant per lease slot by logging in once per slot, and slots then refresh
   independently.
3. **On macOS the refreshed set goes to the keychain, not back to the file.** The lease file
   is deleted on the first save. Read-back on a Mac is `security find-generic-password -s
   "Claude Code-credentials-<sha256(configdir)[:8]>" -w`; inside a seatbelt sandbox without
   keychain access the save path is still untested (EXP-20261016-rq1407).
4. **A dead copy wipes itself**, so a failed lease shows up as an empty token set, not as the
   old one.
5. `claude auth status` with the lease's config dir is a cheap health probe.
