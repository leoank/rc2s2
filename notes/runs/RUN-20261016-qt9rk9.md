## Notes

x86_64-linux build of the same spike as [[RUN-20261016-qqc0qw]], same flake and
sources, submitted from the darwin host and executed on the configured remote builder
(`ssh-ng://ank@spirit`, from `/etc/nix/machines`). Nothing about the builder setup had to
be changed; `nix build` picked it on its own.

Command (from the spike directory):
```
nix build .#checks.x86_64-linux.run --no-link --print-build-logs --print-out-paths
```
That builds `packages.x86_64-linux.libtailscale`, then `packages.x86_64-linux.default`
(ts-hello), then runs the binary inside the builder's sandbox.

Outcome:
- Everything built and ran on the first attempt: 2 m 56 s wall for the whole thing,
  which includes copying the Rust and Go toolchain closure to `spirit`, vendoring the
  Go modules there, the Go build, and `cargo build --release` (0.85 s on 384 jobs).
  The Go derivation's phase lines reached the log but not the `buildPhase completed
  in N seconds` summary, so there is no separate Go build time for linux.
- `libtailscale.a` (linux, after `strip -S`): 30,274,726 bytes. `ts-hello`: 27,958,416
  bytes, PIE, dynamically linked only against `libgcc_s.so.1`, `libc.so.6` and the
  glibc 2.44 loader (`patchelf --print-needed`). No extra `-l` flags were needed on
  linux: `rustc-link-lib=static=tailscale` alone was enough, since Rust's std already
  pulls in pthread/dl/m from glibc.
- Run output (sandboxed, no network):
  `===RESULT=== {"sd": 2752513, "set_dir": 0, "errmsg_rc": 0, "errmsg": "", "close": 0,
  "errmsg_after_close": 9, "target": "x86_64-linux"}`, exit 0. Identical to darwin.
