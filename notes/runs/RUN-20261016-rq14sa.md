## Notes
Tests (a) and (b) of [[EXP-20261016-rq1407]] with the spike binary
(`mxc-spike <policy.json> -- cmd...`, `Containment::Seatbelt(SeatbeltConfig::default())`,
`v1::run`). Policies and logs are in `experiments/EXP-20261016-rq1407/`.

(a) `/bin/echo hi` with an empty policy (`policy-echo.json`, 10 s timeout): stdout `hi`,
exit 0. `test-a-echo.log`.

(b) `curl http://127.0.0.1:18765/` against `python3 -m http.server 18765 --bind 127.0.0.1`
started outside the sandbox:

- `policy-curl.json` = `egress deny, ingress allow, hostLoopback allow`: body
  `hello-from-host`, exit 0. `test-b-curl.log`.
- `policy-curl-egress-only.json` = `egress allow`, no ingress block: `curl: (7) Failed to
  connect to 127.0.0.1 port 18765`, exit 7. `test-b2-curl-egress-only.log`. This is the
  "hostLoopback trap" from the seatbelt backend doc: `ingress.hostLoopback` defaults to
  deny and the profile ends with `(deny network-outbound (remote ip "localhost:*"))`.

So on seatbelt, reaching a host loopback listener costs `ingress.default: allow`, which
also lets the sandbox bind and listen on any address (not scopeable), and `localhost` in a
Seatbelt rule means every address of this machine, not 127.0.0.1.

on uncommitted code; `commit` is the first commit that holds it (0b7a627 in manthan, where the project lived then). It does not
control the macOS release, whose seatbelt implements the profile, and needs port 18765 free.
